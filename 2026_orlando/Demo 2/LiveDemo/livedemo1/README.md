# livedemo1: "Healthy" health and wellness tracker

A responsive implementation of the five screens in the [Health and Wellness Tracker Figma design](https://www.figma.com/design/al1LTJArQcPQDWKYTwpGXI/Health-and-Wellness-Tracker-app), built with React, [Ignite UI for React](https://www.infragistics.com/products/ignite-ui-react) and ApexCharts. It was scaffolded with the [Ignite UI CLI](https://github.com/IgniteUI/igniteui-cli) 16.0.0 (empty React TypeScript template) on top of [Vite](https://vite.dev/).

Part of [Demo 2](../../README.md).

## What the app does

| Route | Page | Features |
| --- | --- | --- |
| `/` | Home | Calendar, daily activities, steps chart and macro breakdown |
| `/activity` | Activity | Period selection, individual/group filtering, selected activity details, heart-rate chart and CSV export (downloads `healthy-activities.csv`) |
| `/nutrition` | Nutrition | Food search, validated add/edit meal dialogs, recalculated calorie totals and adjustable water intake |
| `/sleep` | Sleep | Sleep analysis and four playable, locally generated ambient-tone tracks |
| `/mental-wellness` | Mental Wellness | Practice-level filtering, favorites and guided-session timers |

Any other path shows the Home page.

The header search and notifications work, and the extra sidebar items (Statistics, Profile, Settings, Log out) open demo dialogs. Audio on the Sleep page is synthesized with the Web Audio API after you press Play; it is not a recording or a streamed service, and playback stops when you navigate away.

Branding and photographs in `public/images` were exported from the Figma file. The Titillium Web font is loaded from Google Fonts in `index.html`.

### Data source

There is **no backend**, authentication, connected device or medical advice. All data is fictional and lives in the browser:

- `src/app/wellness-data.ts` holds the navigation, foods, activities and practices, plus a React context (`WellnessContext`) for shared state.
- Some chart and page data is defined inline in the page components and `src/app/ui.tsx`.

Changes (added meals, water intake, favorites) persist while you navigate and reset when you refresh the page. The app makes no network requests apart from loading fonts.

## Prerequisites

- **Node.js 22.12 or later** (npm is included). `igniteui-webcomponents` requires Node 22 or later and Vite 8 requires `^20.19.0 || >=22.12.0`, so 22.12 is the minimum. The CI workflows in this folder use Node 26.x.
- Internet access for `npm install`.
- To run the tests: a Playwright Chromium browser (see [Tests](#tests)).

Check your version:

```sh
node --version
```

## Getting started

From this folder (`Demo 2/LiveDemo/livedemo1`):

```sh
npm install
npm start
```

`npm start` runs the Vite dev server on **http://localhost:3201** (set in `vite.config.ts`, `server.port`, with `strictPort`) and opens it in your default browser. There is no `npm run dev` script.

The commands are the same on macOS, Linux and Windows.

## npm scripts

| Command | What it does |
| --- | --- |
| `npm start` | Start the Vite dev server at http://localhost:3201 with hot reload |
| `npm run build` | Type-check (`tsc -b`), then build a production bundle into `dist/` (Vite is run with a 4 GB Node heap) |
| `npm run preview` | Serve the built `dist/` folder locally (run `npm run build` first; Vite prints the URL) |
| `npm run lint` | Run ESLint with zero warnings allowed |
| `npm test` | Run Vitest in browser mode (Chromium through Playwright), in watch mode |

### Tests

The tests in `src/app/app.test.tsx` run in a real Chromium browser via `@vitest/browser-playwright` (configured in `vite.config.ts`). Install the browser once, then run the suite headless and without watch mode:

```sh
npx playwright install chromium
npm test -- --run --browser.headless
```

They cover meal add/edit calorie totals, meal dialog validation and activity filtering.

### CI and deployment files

`.github/workflows/node.js.yml`, `.github/workflows/github-pages.yml` and `.azure/azure-pipelines.yml` come from the CLI template. They only run when this folder is the root of its own repository; inside the larger VSLive repository GitHub does not pick them up.

To deploy under a sub-path (as the GitHub Pages workflow does), set `VITE_BASENAME` for the router and pass `--base`, for example:

```sh
# macOS / Linux
VITE_BASENAME=/my-app npm run build -- --base=/my-app/
```

```powershell
# Windows PowerShell
$env:VITE_BASENAME="/my-app"; npm run build -- --base=/my-app/
```

## Troubleshooting

**`npm install` fails with engine warnings or errors.** Upgrade to Node.js 22.12 or later.

**`Error: Port 3201 is already in use`.** `strictPort` is on, so Vite stops instead of switching ports. An earlier run is probably still going. To change the port permanently, edit `server.port` in `vite.config.ts`. To find what is using the port:

```sh
# macOS / Linux
lsof -i :3201
```

```powershell
# Windows
netstat -ano | findstr :3201
```

**Tests fail with a missing browser or executable error.** Run `npx playwright install chromium` and try again.

**`npm run build` fails with TypeScript errors.** The build runs `tsc -b` first with strict settings (`noUnusedLocals`, `noUnusedParameters`). Fix the reported errors, or run `npm start`, which does not type-check.

**Components render unstyled.** `src/main.tsx` must import `igniteui-webcomponents/themes/light/material.css`. That package is installed as a dependency of `igniteui-react`.

**Text uses a fallback font.** Titillium Web loads from Google Fonts, so the font needs internet access.

**The page is blank after a refresh on a deep link when hosted statically.** Configure the host to serve `index.html` for unknown paths (the GitHub Pages workflow copies `index.html` to `404.html` for this).
