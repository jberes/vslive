# Dispatch Console – Implementation Plan

Base: `Haiku/dispatcher` (Ignite UI for React 19.9, Vite, react-router). API: `Backend/DispatchApi` on `http://localhost:5207`.
Direction: **A. Operations Ledger** (primary). Corridor Control and Shift Planner are out of scope for this build.

## Libraries (confirmed via igniteui-cli and theming MCP)
- UI: `igniteui-react` (OSS). Grids: **Grid Lite** (`igniteui-react/grid-lite`, `igniteui-grid-lite@0.11`). Date entry: `IgrDatePicker`, `IgrDateTimeInput`.
- Charts: **ApexCharts** (`react-apexcharts`), as the brief specifies.
- Scheduling: the library has `IgrCalendar`, `IgrDatePicker`, `IgrDateRangePicker` only. There is **no timeline/scheduler component** in the OSS set. The reschedule view therefore uses Grid Lite plus date/time inputs, not a Gantt.
- Theme: Fluent, generated by the theming MCP from primary `#155dfc`. Base component theme is `igniteui-webcomponents/themes/light/fluent.css`, with the palette overrides in `src/styles/theme.css`.

## Route map
| Route | Screen | Journey |
|---|---|---|
| `/` and `/jobs/:jobId` | Operations Ledger: unassigned/open queue (Grid Lite), filters, persistent details panel with ranked crews and dry-run validation | 1 Assign a job |
| `/schedule` | Crew reschedule: technician board (Grid Lite), selected crew's day jobs, reschedule panel with impact preview | 2 Reschedule a technician |
| `/sla` | SLA risk: summary tiles, due-by-hour and trend charts (ApexCharts), at-risk grid | 3 Today's SLA risk |
| `/urgent` | Urgent fault intake: location, impact, priority, create job, then route to assignment | 4 Urgent infrastructure fault |
| `/handover` | Shift handover: unresolved jobs, incoming owner, handover note written as job notes | 5 Shift handover |

Location context (region) and the acting dispatcher sit in the persistent header on every route. Filters and selection are kept in the URL query string, so they survive opening job details.

## Data
- Clock: `GET /api/meta/clock`. Every timestamp is shown in operations-local 24-hour time. The API has no offset, and regions are `America/New_York`. See open question on JST.
- Polling every 30 s. A list is **stale** after 90 s without a successful refresh. A failed request shows **disconnected**.
- Assign: `GET recommendations` + `GET validate-assignment` (dry run) → impact dialog → `POST assign`.
- Reschedule: board from `GET dispatch/board`; impact computed from board jobs (overlaps, shift bounds). Then `POST jobs/{id}/reschedule`.
- Conflicts: before a save, re-fetch the job and compare `updatedAt` with the version the user loaded. If it changed, show a conflict outcome and do not save. A 409 from the server shows its issues.
- SLA: `GET sla/summary`, `GET sla/at-risk`, `GET sla/trend`.
- Urgent: `POST /api/jobs` with priority Critical or High.
- Handover: no handover endpoint exists. Each handover item is written as a job note via `POST /api/jobs/{id}/notes` (internal). Incoming owner is recorded in the note body.

## Permissions
Roles come from `/api/dispatchers` (`Dispatcher`, `SeniorDispatcher`, `Supervisor`).
- Dispatcher: assign, reschedule, urgent intake, handover.
- SeniorDispatcher and Supervisor: additionally may override a blocking validation (`force: true`) and reassign-day.
The acting dispatcher is chosen in the header for this demo; there is no login.

## Quality bar (from brief)
- Status is never colour-only: each SLA/state chip has an icon and text.
- Japanese UI labels (dictionary in `src/i18n/ja.ts`); data values stay as delivered.
- Grid rows with two-line cells use ≥56 px height, with dividers.
- Loading, empty, stale, disconnected and conflict states are each rendered.
- Every route is screenshotted at 1920 px, inspected, fixed, and re-captured.
