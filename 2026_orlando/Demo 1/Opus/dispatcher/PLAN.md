Direction: **A. Operations Ledger** (primary), with **Shift Planner** and **Corridor Control** as focused views
that share the same filters, status language, and job details.

**Scheduling components:** Ignite UI React OSS ships Calendar, Date Picker, Date Range Picker and Date-Time Input — there is
no scheduler/Gantt in the OSS set. The crew timeline therefore uses the ApexCharts **rangeBar timeline** (library chart,
not hand-rolled); editing happens through the Date Picker / Date-Time Input in a reschedule dialog.

**Theme:** Fluent light theme (`igniteui-webcomponents/themes/light/fluent.css`) + palette generated by the theming MCP
(`create_theme`, designSystem `fluent`, primary `#155dfc`) in `src/styles/theme.css`. ApexCharts uses its
**Ignite UI add-on** (`apexcharts/features/ignite-ui`) so charts read the same `--ig-*` Fluent tokens; semantic
series (breached / at-risk / on-track / met) are pinned to the palette's error / warn / primary / success tokens.

## Cross-cutting design

- **Persistent location context**: region selector in the top bar (stored in `localStorage` and the URL); every view and
  chart is scoped to it; detail shows Region › Line › Station › Asset.
- **Filters + selection survive navigation**: ledger state lives in URL search params, mirrored to `sessionStorage`;
  opening `/jobs/:id` and returning restores both.
- **Role-based permissions** (`Dispatcher` / `SeniorDispatcher` / `Supervisor`, from `/api/dispatchers`, selectable as
  "signed in as" because the API has no auth):
  - Dispatcher: assign, reschedule, status, notes, raise urgent faults; priority changes High↔Medium↔Low only.
  - Senior dispatcher: + set or clear Critical priority, reassign a crew's day.
  - Supervisor: + override blocking validation (forced assignment/reschedule) with a recorded reason.
  - Blocked actions offer "Request supervisor approval" (recorded as a job note, listed in handover as pending).
- **Every change is recorded**: `dispatcherId` on every mutation, plus a note for overrides and handovers.
- **Simultaneous edits (40 dispatchers)**: the API has no row versions, so before each save the console re-reads the
  job and compares `updatedAt` / status / crew / start. A mismatch opens a conflict dialog showing what changed and by
  whom; the dispatcher reloads or re-applies explicitly. Every save ends in an explicit outcome (saved / blocked with
  validation issues / conflict / failed) — never silent.
- **Freshness**: operations clock from `/api/meta/clock` (EST, 24 h). Views poll every 30 s; header shows
  "Updated hh:mm:ss"; data older than 90 s is marked **Stale**; failed polls show a **Disconnected** banner with retry.
- **Status language** (never color-only): every SLA / priority state = icon shape + text + color.
  Breached ⛔ red · At risk ▲ amber · On track ● blue-gray · Met ✓ green. Critical ◆ / High ▲ / Medium ■ / Low ○.
- **Service targets vs safety restrictions** are separate panel sections.
- **Grid density**: stacked two-line cells, ≥ 56 px rows, vertical cell padding, line spacing, visible row dividers.
- **States**: loading (progress bar + skeleton text), empty, stale, disconnected, conflict — designed per view.
- **Accessibility**: keyboard reachable rows (row-open button in first column), visible focus ring, AA contrast,
  `aria-live` save outcomes.

## Implementation order

1. Theme + shell (navbar, region context, user/role, ops clock, connection state), API client, shared status components.
2. Ledger + detail panel + assign dialog (recommendations, validation preview, conflict check).
3. Job record page.  4. SLA risk.  5. Shift Planner + reschedule dialog.  6. Urgent fault.  7. Handover.  8. Corridor.
9. Screenshot every route at 1920 px with Playwright, inspect, fix, re-capture.

## Known gaps (backend)

No handover, approval or concurrency endpoints exist: handovers and approval requests are recorded as job notes plus a
local record; conflict detection is client-side. Live push is not available, so updates are polled (provisional
requirement per brief). Integration names for maintenance/asset/workforce systems remain unconfirmed.
